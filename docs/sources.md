# Sources, attribution and evidence boundaries

[README](../README.md) · [Publication status](../PUBLICATION-STATUS.md)

This release contains original tools, selected profile data and documentation. No private note was copied wholesale, no raw inventory or unique device identifier is shipped, no Samsung script/binary is redistributed, and no third-party source code was copied. Attribution does **not** grant a license to copy code; verify a project's actual license and chosen revision before any future reuse.

## Local evidence ledger

The labels below refer to authentic private records read selectively during preparation. They identify what supports each claim without exposing local paths, unique IDs, credentials or raw evidence. They are **not public downloadable exhibits**, so the public tree alone cannot independently prove the complete private history. Exact private source paths/hashes are retained separately for owner review.

| Label | Record family selectively inspected | Supports | Does not establish |
| --- | --- | --- | --- |
| L0 | Private operator note: current accepted state, identity, backup/workflow history, official-source references and later human confirmations | Exact tested identity; historical timeline; owner consent/mic/HbbTV and general acceptance | Every older “pending” paragraph remains current; complete per-app matrix |
| L1 | Authentic 8-target advertising `apply.sql` / `restore.sql`, operational guard/marker excerpts | Exact IDs, text flags, original per-row tuples and inverse parity; two markers/three consumers | Generic cross-model uninstall list or independently new live test |
| L2 | Authentic 15-target voice `apply.sql` / `restore.sql`, operational and inverse excerpts, selected plan fields | Exact IDs, original per-row tuples, three typed preferences, three markers/consumers, process-selection boundary | That flags or TERM alone stop every live process |
| L3 | Accepted R3 archive: handoff, candidate specification, selected renderer structure, independent quality report | Mechanism, preserved signed stock, hook-only inverse, complete offline fixture roundtrip and reviewed boundaries | That the public adaptation is newly hardware-tested; the candidate's old “pending” text is final operational status |
| L4 | Final automatic-reapplication acceptance and its underlying **six-command native read-only receipt** | Changed kernel boot; fresh success; two masked/inactive/PID0 units; exact 23 selected rows among 499; three false preferences; shared units active; process classification and cleanup | Continuous monitoring, zero telemetry, early-boot exclusion, full functional matrix or live inverse execution |

The selected-component JSON was mechanically extracted from L1/L2 apply guards, crosschecked against their inverse tuples and operational statements, then matched against selected rows in L4. The profile has **8 + 15 = 23 unique IDs**, not a hand-transcribed broad package inventory. Only the selected projection is included. Original before values are historical evidence, **not portable rollback instructions**.

Conflicts are resolved by **accepted final receipts and authenticated current readback over historical plans**. Earlier candidate specifications can document a safety mechanism while their installation/persistence “pending” status has been superseded by L4. Conversely, L4's operational success does not turn offline restore tests into a live restore.

## Public projects and their different scopes

- **chris-ritsen/samsung-tv-root** is the credited upstream temporary-access/rooting project used as the access reference. It is not this Q70D privacy profile and does not supply its AT-HUB privacy hook.[1]
- **invaliddayta/s90c-tools** is a relevant Samsung debloat precedent associated in prior research with **QE77S90CATXXN / Tizen 7** and a removal workflow. Its targets/method are not interchangeable with this Tizen 8 registry-disable plus hook workflow.[2]
- **ardazeytin/samsung-tizen-tv-debloat** is another general Samsung Tizen debloat/storage/uninstall guide, not the implementation of this Q70D boot hook.[3]

GitHub repository metadata checked on 2026-10-23 showed: root upstream default branch `master`, license **Unlicense**; s90c-tools default branch `main`, **MIT**; ardazeytin default branch `main`, **MIT**. Repository metadata is not an audit or license clearance for an unpinned source copy. Pin and review the actual source, release and license before reuse.

**No exact guide was found in the searches performed on 2026-10-23.** GitHub repository searches for Q70D debloat, exact TQ55Q70DATXXC, T-PTMLDDEUC privacy and the exact visual-service term each returned zero results; web searches found general guides. Repository search and web indexing are incomplete, so this is not a claim that no guide exists or that this work is the first.

## Official references, with limits

- Samsung's developer-mode/device documentation is an official access-setup reference; actual firmware/menu labels must still be observed.[4]
- The Spanish viewing-information notice describes a separate ACR/viewing-information consent and its withdrawal; its policy wording is not traffic measurement of this TV.[5]
- The Spanish interest-based advertising notice covers a separate consent. Withdrawing it is not a promise of no ads or control over third-party apps.[6]
- A **later 2025 European e-manual** documents Terms & Privacy / Privacy Choices (PDF page 47 in the retained reference), not exact menu wording on installed firmware 1400/Tizen 8.[7]
- A later quick-start guide covering **Q7*D** describes the TV microphone switch and its effects (Spanish section page 6, PDF page 22 in the retained reference). It does not prove that the TV switch electrically disconnects the separate remote-control microphone.[8]

The official URLs below come from the source references used during the TV work. Their current contents were not fetched again for this release. Check menu/software differences and document revisions on the actual TV. Social-media performance claims are not measurements of this set.
